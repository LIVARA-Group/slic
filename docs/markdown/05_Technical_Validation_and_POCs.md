# 1. Purpose
Close the highest-risk technical decisions **before** broad implementation, using reproducible experiments rather than marketing comparisons. This document specifies ten POCs; their **Results fields are intentionally empty** — nothing in this package is a measured result.

# 2. Scope
Local database, OPFS, graph, search, background processing, graph visualisation, sync conflicts, cryptography/recovery, Investigative isolation and ingestion sandboxing. Each POC records the ADR it feeds.

# 3. Dependencies
WP-010 (harness and generators) precedes all POCs. Threat-model baseline (WP-008) precedes POC-08/09. Research Pack 03§13 (POC-A…E) @SD@ is mapped as: POC-A → 01/02/05; POC-B → 07/08; POC-C → 03/04; POC-D → 09; POC-E → 10.

# 4. Requirements
## 4.1 Method (applies to every POC) @SD@ + @R@
Every benchmark publishes: hardware, OS, browser/runtime versions, dataset generator and seed, dataset size and distribution, warm/cold state, concurrency, operation mix, run count, percentile reporting, memory measurement method and raw results (Research Pack 06§4 @SD@). Headline claims from one laptop or one hand-picked graph are not acceptable.

## 4.2 Proposed gate thresholds (proposals, not SLAs) @OD@
Numbers are needed to decide, but no honest numbers exist before a baseline. The following are **candidate thresholds for the product owner to ratify or replace before running POC-01**; none is a measured result or a promise.
| Item | Candidate gate | Rationale |
|---|---|---|
| Main-thread task during typing/save | no task >50 ms attributable to SLIC | common web long-task convention (@R@); source target 'sub-15 ms typing' @SD@ is a stretch goal to measure |
| Capture commit ack (S/M datasets) | p95 within a value set by product (placeholder: ≤100 ms) | perceived-instant feedback; to be replaced by baseline-informed value |
| Local search (M dataset) | p95 within a value set by product (placeholder: ≤100 ms) | interactive search; measured vs. exact scan |
| 2-hop neighbourhood (typical degree) | p95 within a value set by product (placeholder: ≤100 ms) | navigation responsiveness |
| Crash loss | 0 acknowledged writes lost | hard gate (REL-001) |
| Runtime memory | recorded; budget set after baseline (source 'sub-80 MB' target @SD@) | stated target, unverified |

## 4.3 Common datasets
Generated by `test-kit` with fixed seeds, versioned generators and checksums of outputs. Families: DS-P (Personal objects), DS-G (graphs), DS-T (text + gold queries), DS-A (attachments), DS-C (crypto), DS-I (hostile files). Real user data is never used.

## 4.4 Common environment
Declared by the executor in the environment manifest: CPU model/cores, RAM, storage type and free space, OS+version, browser+version for each matrix browser, power mode. Minimum recommended: one low-end and one mid-range reference device per matrix browser (OQ-06). No result is valid without the manifest.

## POC-01 — Local database engine
| Field | Content |
|---|---|
| **POC ID** | POC-01 |
| **Hypothesis** | At least one candidate meets all correctness gates and the access-pattern budget for Personal v1.0 without loss of acknowledged writes. |
| **Question** | Which of IndexedDB, SQLite-WASM (OPFS-backed) or SQLite-WASM (alternative VFS) satisfies durability, query, graph and migration needs with the least operational risk? |
| **Candidate Technologies** | IndexedDB (native API; optionally via a thin wrapper), SQLite-WASM with OPFS VFS variants, SQLite-WASM in-memory + snapshot (control) |
| **Test Environment** | Browser matrix per OQ-06 (or server stack in Compose for POC-09/10); versions recorded; clean profiles; no extensions |
| **Hardware** | Declared by the executor in the environment manifest: CPU model/cores, RAM, storage type and free space, OS+version, browser+version for each matrix browser, power mode. Minimum recommended: one low-end and one mid-range reference device per matrix browser (OQ-06). No result is valid without the manifest. |
| **Dataset** | DS-P-S (1k objects), DS-P-M (10k), DS-P-L (100k) generated by `test-kit` with fixed seeds; mix 40% notes (0.5–20 KB), 25% entities, 25% relations, 5% sources/observations, 5% claims; revisions: 1–30 per note, Zipf-distributed. |
| **Dataset Size** | S: ~10^3 objects; M: ~10^4; L: ~10^5 (matches 1k/10k/100k entity sizes in Research Pack 06§4 @SD@); plus 1–20 attachments of 1–50 MB for POC-02. |
| **Test Scenarios** | (1) Single-object commit latency, cold and warm. (2) Multi-object transaction (note + revision + backlinks + outbox) of 5–50 objects. (3) Batch import 10k objects. (4) Point reads, range scans, index lookups (alias, predicate, tx_to IS NULL). (5) 1-hop and 2-hop neighbourhood from DS-G datasets. (6) Two tabs writing concurrently (same and different objects). (7) Crash injection: kill tab/worker at random points over 1000 transactions, with an ack ledger. (8) Schema migration N-1→N on DS-P-L. (9) Quota exhaustion. (10) Persistent-storage grant/deny behaviour. (11) Restart persistence. (12) Browser matrix run. |
| **Measurement Method** | Median and p95/p99 over ≥30 runs per scenario after warm-up; separate cold runs; main-thread long tasks via Performance observer; memory via browser-supported measurement APIs with the method recorded; disk growth; raw JSON results archived with seed, versions and manifest. |
| **Baseline** | Control A: raw IndexedDB without wrapper. Control B: in-memory store with periodic snapshot (shows the cost of durability). No external numbers are used. |
| **Results** | **NOT EXECUTED** — to be filled with raw-result links, environment manifest and summary |
| **Limitations** | Synthetic data; one run family per hardware class; browser internals change between versions — results are time-stamped and must be re-run on major version changes; storage behaviour under real user eviction is observed only through simulation. |
| **Reproducibility Instructions** | `test-kit bench poc01 --seed 20261115 --dataset S|M|L --engine idb|sqlite-opfs-… --out results/`; harness, dataset generator and ack-ledger checker are versioned in the repository (WP-010). Second engineer must reproduce relative ordering. |
| **Decision** | **Hard gates (zero tolerance):** no lost acknowledged write in crash injection; no partial multi-object transaction visible; migration interruption recoverable; integrity checker clean after every scenario. **Then**: choose the simplest candidate that meets the proposed thresholds in §4. Prefer IndexedDB when it passes all gates (no COOP/COEP requirement, smaller footprint); choose SQLite-WASM-OPFS only if IndexedDB fails query/graph/migration gates and SQLite passes all hard gates. If none passes: ADR-010 trigger evaluation and scope re-plan (doc 01 §10). |
| **ADR Reference** | ADR-004 |
| **Work package** | WP-011 |

# 6. Technology
Candidate technologies are listed per POC. Inclusion is not endorsement. Verification status of facts used in POC design: IndexedDB transaction durability is a *hint* (strict/relaxed/default) @V@ (MDN, level 1); best-effort vs persistent storage and `navigator.storage.persist()` @V@ (MDN, level 1); OPFS VFS header requirements for SQLite-WASM — secondary sources only (level 4), **to be confirmed against sqlite.org in POC-02**.

# 7. Implementation
1. Build harness and generators (WP-010): CLI, seed handling, environment manifest collector, result schema, ack-ledger checker, report generator. 2. Validate the harness itself (generator determinism, ledger correctness) with a trivial engine. 3. Implement each candidate adapter behind the same storage/query port. 4. Run, archive raw results, summarise. 5. Second engineer reproduces. 6. Write ADR outcome. 7. Update documents and labels (@OD@ → @V@/@R@).

# 8. Data & Contracts
Result record: `{poc_id, scenario, candidate, dataset_id, seed, environment_manifest_id, runs[], percentiles{p50,p95,p99}, memory, failures[], raw_uri}`. Manifest schema: hardware, OS, browser/runtime versions, flags, power state.

# 9. Security
POCs use synthetic data only. POC-08 prototype code is non-production and must not be reused without review. POC-09/10 run in isolated environments; hostile corpus stored and handled as malware samples (no execution outside sandboxes).

# 10. Failure Handling
Inconclusive results → refine protocol, do not decide. Contradictory results across browsers → decide for the declared matrix and record the limitation. No candidate passes hard gates → doc 01 §10 re-plan. A POC that cannot be reproduced is not evidence.

# 11. Testing
Harness self-tests; determinism test of generators (same seed → same checksum); independent reproduction check; review of raw results by someone other than the author.

# 12. Acceptance Criteria
SG1: all ten POCs executed (or explicitly Deferred with trigger, e.g. POC-06 for visual graph), raw results archived, ADR-004/005/017/019 recorded, reproducibility confirmed, blockers listed.

# 13. Deliverables
Harness, generators, per-POC reports, raw results, ADR updates, updated risk register.

# 14. Risks
RK-11 (no candidate meets gates), RK-13 (targets misread as promises), RK-05 (eviction/corruption realism), RK-20 (stale facts).

# 15. Open Decisions
Ratification of §4.2 thresholds; OQ-06 matrix; OQ-14 languages for DS-T; gold-set ownership.

# 16. References
